\section{External libraries used}
The following libraries were used in the project:
\begin{itemize}
    \item \textbf{numpy} (chat.py) \\
    used for weighted random selection of group members based on activity 
    \item \textbf{emoji} (analyze.py) \\
    used to detect and extract emojis from message
    \item \textbf{datetime} (chat.py and analyze.py) \\
    used for parsing timestamps and computing time difference between messages
    \item \textbf{json} (analyze.py) \\
    used to store computed statistics in structured json file 
    \item \textbf{re} (analyze.py) \\
    used for parsing chat messages using regular expressions
    \item \textbf{random} (chat.py) \\
    used for generating random messages and probabilities
    \item \textbf{sys} (analyze.py and chat.py) \\
    used for command line argument parsing
\end{itemize}

\section{Chat Generator (chat.py)}

The file \texttt{chat.py} generates a WhatsApp group chat over a fixed time period. 
The chat simulates multiple users with different personalities and behaviours, making the dataset realistic

\subsection*{1. Vocabulary-based Message Generation}

The function \texttt{load\_vocabulary()} reads words from an external file (vocabulary.txt). 
Messages are constructed by randomly selecting words from this vocabulary, ensuring variation in content
\subsection*{2. Personality-driven Users}

Each user is defined using a configuration dictionary containing:
\begin{itemize}
    \item Name and personality type
    \item Behaviour traits (chatterbox, hype, emoji, dry, essay, ghost, lurker, conversation\_starter, night\_owl)
    \item Frequency weight (how often the user sends messages)
    \item Hour-wise activity distribution (each user has a 24 hour activity profile that controls when they are active) (this ensures that some users are active during the data, while others are active at night)
    \item Message length range
    \item Response delay
and using these configurations the messages are generated in the group chat \\
Messages may include emojis based on a probability defined in user traits. 
Some users (e.g., emoji-heavy personalities) include multiple emojis in a message
\end{itemize}

\subsection*{3. Weighted User Selection}

The next user to send a message is selected using weighted random selection. 
The weight depends on:
\begin{itemize}
    \item Frequency of the user
    \item Time of day
    \item Recent activity in the chat
\end{itemize}

\subsection*{4. Conversation Dynamics}

The program models realistic conversation behaviour:
\begin{itemize}
    \item Active users are more likely to respond in busy chats
    \item Conversation starters are more likely after long silence
    \item Users who recently sent messages are less likely to speak again immediately
\end{itemize}
Users can send multiple messages consecutively:
\begin{itemize}
    \item Controlled by streak probability
    \item Number of messages determined by minimum and maximum streak length
\end{itemize}
Some users become inactive after sending a burst of messages. 
This is implemented using a silence period after a streak.

\subsection*{5. Message Rate Limiting}

Each user has a limit on how many messages they can send within a time window. 
If the limit is exceeded, their probability of being selected is reduced.

\subsection*{6. Time Gap Simulation}

The function \texttt{time\_gap()} controls the delay between messages:
\begin{itemize}
    \item Short gaps (seconds) for quick replies
    \item Medium gaps (minutes) for normal conversation
    \item Long gaps (hours) to simulate silence
\end{itemize}

\subsection*{7. Recent Activity Tracking}

The program keeps track of recent messages for each user. 
This helps:
\begin{itemize}
    \item Prevent the same user from dominating the chat
    \item Maintain realistic turn-taking
\end{itemize}

\subsection*{8. Timeline Simulation}

The chat is generated over a fixed timeline:
\begin{itemize}
    \item Start date: July 2024
    \item End date: November 2024
\end{itemize}

Time always moves forward during simulation.

\subsection*{9. Output Format and command line interface}

The generated chat is stored in \texttt{chat.txt}. 
Each message follows the format:
\texttt{DD/MM/YY, HH:MM - Name: Message} \\

The script accepts input using command-line arguments:
\begin{itemize}
    \item Vocabulary file path (required)
    \item Output file path (optional)
\end{itemize}

\section{Statistics Parser (analyze.py)}

The file \texttt{analyze.py} processes the generated chat file and computes various statistics 
to analyse user behaviour. The results are stored in a structured JSON file for use in the front-end.
the input is the file generated by the chat.py and each line is parsed to extract date, time, sender, and message content

\subsection*{Global Statistics and Per-user Statistics}

\begin{itemize}

\item \textbf{Total Messages in Group} \\
Total number of messages sent across all users.

\item \textbf{Busiest Day} \\
The date with the highest number of messages.

\item \textbf{Longest Silence} \\
The maximum time gap between two consecutive messages in the chat. 
The result includes duration (in hours and days) and the start and end timestamps.

\item \textbf{Overall Emoji Usage} \\
Counts all emojis used in the chat and identifies the most frequent ones.

\item \textbf{Most Used Emojis} \\
Extracts the top 3 most frequently used emojis for each user.

\item \textbf{Total Messages} \\
Counts the number of messages sent by each user.

\item \textbf{Word Count} \\
Counts the total number of words sent by each user. Emojis are also counted as words.

\item \textbf{Average Response Time} \\
Calculates the median time (in minutes) between a user's message and the next reply 
from a different user, considering only responses within 60 minutes.

\end{itemize}

\subsection*{Personality Classification}

Based on the computed statistics, each user is assigned one or more personality labels:

\begin{itemize}
    \item \textbf{The Chatterbox} --- sends rapid-fire short messages all day long, 
    with a significantly higher message count than any other member
    \item \textbf{The Dry Texter} --- replies with the fewest words per message, 
    rarely uses emojis, and never writes long responses
    \item \textbf{The Essay Writer} --- sends the longest messages on average, 
    slow to respond but writes detailed multi-sentence replies
    \item \textbf{The Night Owl} --- largely inactive during the day, 
    with the majority of messages sent between 12 AM and 4 AM
    \item \textbf{The Lurker} --- present in the chat but rarely responds, 
    with the lowest message count and near-zero conversation starts
    \item \textbf{The Emoji Queen} --- includes emojis in almost every message, 
    often using multiple emojis per message
    \item \textbf{The Hype Person} --- fastest average reply time, 
    more likely to respond when the chat is already active
    \item \textbf{The Conversation Starter} --- most frequently sends the first message 
    after a long silence, keeping the group chat alive
    \item \textbf{The Ghoster} --- appears in bursts of consecutive messages 
    then vanishes for hours, with enforced silence after each streak
\end{itemize}

\subsection*{Output}

All computed statistics are stored in \texttt{data.json} in a structured format, 
which is later used by the front-end for visualisation.

\section{Custom Statistic: Conversation Killer}

\subsection*{Definition}
A message is considered a \textit{conversation killer} if no other user sends a message 
within 60 minutes of it. The killer score for each user is computed as:

\[
\text{Killer Score} = \frac{\text{Number of conversation-killing messages}}{\text{Total messages sent}} \times 100
\]

\subsection*{Why This Statistic?}
Standard analytics tools track message volume and response times, but none capture who 
\textit{ends} conversations. A user can be highly active yet consistently send messages 
that kill the chat's momentum. This metric surfaces that social dynamic.

The 60-minute threshold is consistent with the conversation\_starter metric, 
making the two a pair, a conversation killer triggers the silence that a 
conversation starter later breaks.

\subsection*{What the Data Reveals}
Kavya has the highest killer score (6.67) despite sending only 15 messages, meaning the 
rare times she speaks, the conversation tends to die. Aryan has the lowest score (1.86) 
despite the most absolute kills (32), because his high message volume keeps the ratio small.
